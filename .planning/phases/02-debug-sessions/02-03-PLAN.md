  <name>Task 1: Create trace-monitor utility for watch mode polling and progress display</name>
  <files>src/utils/trace-monitor.ts</files>
  <action>
Create new file `src/utils/trace-monitor.ts` with watch mode monitoring logic (per RESEARCH.md Pattern 3 and Code Examples). Export:

**watchTraceFlag(org: Org, traceId: string, expirationDate: string, logger: { log: (msg: string) => void }): Promise<void>**

Implementation details:

1. **Setup:**
   - Import cliProgress from 'cli-progress'
   - Convert expirationDate (ISO 8601 string) to millisecond timestamp: `const expireTime = new Date(expirationDate).getTime()`
   - Calculate maxDuration = 24 * 3600 * 1000 (24 hours in milliseconds)

2. **Progress bar creation:**
   - Create SingleBar with format: `'Trace monitoring [{bar}] {percentage}% | {value}m remaining | Expires {expiry}'`
   - Options: hideCursor: true, fps: 0.5 (update twice per second), autopadding: true, noTTYOutput: false
   - Use cliProgress.Presets.shades_classic for styling
   - Call progressBar.start(maxDuration, 0, { expiry: formatted time string })

3. **SIGINT (Ctrl+C) handler:**
   - Define onSignal callback:
     ```
     const onSignal = () => {
       logger.log('');  // newline for cleanliness
       progressBar.stop();
       logger.log('Monitoring interrupted.');
       process.exit(0);
     };
     ```
   - Register handler BEFORE starting progress bar: `process.on('SIGINT', onSignal)`
   - Unregister handler when watch ends: `process.removeListener('SIGINT', onSignal)`

4. **Polling loop:**
   - Use setInterval with 1-second (1000ms) interval
   - Each iteration:
     a. Get current time: `const now = Date.now()`
     b. Calculate remaining time: `const remaining = Math.max(0, expireTime - now)`
     c. Calculate remaining minutes: `const remainingMinutes = Math.floor(remaining / 60000)`
     d. Calculate progress value (0 to maxDuration): account for time elapsed
     e. Update progress bar: `progressBar.update(progressValue, { expiry: formattedTime, remaining: remainingMinutes })`
   - Check exit condition: if remaining <= 0:
     - clearInterval(intervalId)
     - process.removeListener('SIGINT', onSignal)
     - progressBar.stop()
     - logger.log('Trace flag expired. No more logs will be generated.')
     - return (exit function)

5. **Error handling:**
   - Wrap setInterval in try/catch (prevent unhandled errors in loop)
   - If error occurs, stop progress bar, unregister SIGINT handler, and throw

6. **Time formatting:**
   - Format expirationDate for display in progress bar: use `toLocaleTimeString('en', { timeZone: 'UTC' })`
   - Example: "14:30:45 UTC"

Per RESEARCH.md Pitfall 3, ensure progressBar.stop() is called before process.exit() to avoid terminal corruption. Per Pitfall 2, check expiry every cycle to detect when trace expires.

The function is async but does not need to query Salesforce API in the loop (per CONTEXT.md D-04, Phase 2 only monitors, Phase 3 downloads). Pure time-based monitoring is sufficient for v1.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CLI process → OS signal handlers | SIGINT signal from terminal to Node.js process |
| Progress bar → Terminal | cli-progress library controls terminal cursor and ANSI codes |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-11 | Denial | Infinite polling loop consumes 100% CPU | mitigate | Use fixed 1-second interval (not busy loop); cli-progress handles terminal updates efficiently |
| T-02-12 | Information Disclosure | SIGINT not handled, terminal left in corrupted state | mitigate | Implement process.on('SIGINT') with progressBar.stop() before exit (per RESEARCH.md Pitfall 3) |
| T-02-13 | Denial | setInterval registered without unregister, orphaned timers consume memory | mitigate | clearInterval(intervalId) when trace expires or SIGINT fires; process.removeListener() for signal handler |
| T-02-14 | Tampering | User sends multiple SIGINT to cause undefined behavior | mitigate | SIGINT handler immediately exits via process.exit(0); subsequent signals ignored |
| T-02-15 | Information Disclosure | Sensitive org info displayed during monitoring | accept | Progress bar only displays expiry timestamp and percentage; no credentials or user details exposed |
</threat_model>
