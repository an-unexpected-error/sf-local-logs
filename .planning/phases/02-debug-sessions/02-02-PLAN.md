  <action>
Update `src/commands/log/trace.ts` with full implementation (extending the existing scaffold). Implement the trace command class with:

**Flags (in static readonly flags):**
- `target-org`: Already present, required org
- `api-version`: Already present, org API version
- `user-id`: Already present (string, not required) — used for explicit bypass of interactive search (Phase 3 will add interactive; for now just accept the flag)
- `level`: NEW — optional string flag with summary "Debug level to apply (DEBUG, INFO, WARNING, ERROR). Defaults to org's default level."
- `no-watch`: NEW — optional boolean flag with summary "Exit immediately after creating trace flag (skip monitoring). Default: false (watch mode enabled)."
- `overwrite`: NEW — optional boolean flag with summary "Stop existing trace flag and create a new one. Default: false."

**Static properties:**
- Update `summary` to reference messages
- Update `description` to reference messages
- Update `examples` to reference messages

**run() method logic:**
1. Parse flags via `await this.parse(Trace)`
2. Get target org: `const org = flags['target-org']`
3. Validate --user-id provided (for now; Phase 3 adds interactive search)
   - If not provided, throw error: "User ID required. Use --user-id <id> or use interactive search in Phase 3."
4. Query default DebugLevel if --level not provided:
   - Call `getDefaultDebugLevel(org)` from trace-helper
   - If provided, use flags.level (as provided)
   - Store selected debugLevelId
5. Check for existing active trace flag:
   - Call `checkExistingTraceFlag(org, userId, flags.overwrite)`
   - If exists=true and overwrite=false, error was already thrown by helper; catch and re-throw with user guidance
   - If exists=true and overwrite=true, show status message: "Stopping existing trace for {userId}..."
6. Create new TraceFlag:
   - Call `createTraceFlag(org, userId, debugLevelId)`
   - Catch errors and display meaningful messages (permission denied, user not found, etc.)
7. Query user details (name, email) for display:
   - Execute SOQL: `SELECT FirstName, LastName, Email FROM User WHERE Id = '{userId}' LIMIT 1`
   - Use org.getConnection().query() (not tooling)
8. Query DebugLevel name for display:
   - Call `getDebugLevelName(org, debugLevelId)` to get "Debug" instead of ID
9. Format and return TraceResult:
   - Return { traceFlag: { id, userId, userName: `${firstName} ${lastName}`, userEmail, debugLevel: levelName, expirationDate } }
   - Do NOT enter watch mode yet (Wave 3)

All error handling should catch Salesforce API errors and display user-friendly messages via messages.getMessage() calls (not raw API errors). Use the patterns from Phase 1 (search.ts) for consistent error handling style.

Per CONTEXT.md D-26, respect --target-org flag for multi-org environments (already handled by Flags.requiredOrg()).

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CLI flag → Salesforce API | User-provided user ID and debug level ID cross into Salesforce API |
| Salesforce API response → display | Trace flag and user details returned from API; sensitive data should be filtered |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-06 | Tampering | User ID input validation bypassed | accept | Per D-19, no pre-validation; let Salesforce API reject invalid IDs; show error message with remediation |
| T-02-07 | Information Disclosure | Raw API errors exposed to user | mitigate | Catch Salesforce API errors; translate to user-friendly messages via messages.getMessage(); log raw error only in --debug mode |
| T-02-08 | Elevation | User creates trace for another user they shouldn't access | accept | Salesforce API enforces permission boundary; if user lacks TraceFlag creation right, API rejects; we show error message |
| T-02-09 | Information Disclosure | Permission denied message leaks internal details | mitigate | Translate raw error to generic "contact admin" message; offer --debug flag for technical users to see raw error |
| T-02-10 | Denial | Multiple rapid trace creation attempts exhaust API quota | mitigate | No retry logic (per D-22); user can re-run manually; LIMIT 1 on queries prevents unbounded operations |
</threat_model>
