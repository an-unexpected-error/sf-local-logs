    NUT files use @salesforce/cli-plugins-testkit's execCmd to run commands through the
    actual sf CLI. In Phase 0, since commands are stubs, NUTs only verify that:
    1. The command is registered and discoverable
    2. The command exits with code 0 when run with --help

    Template for each NUT (example for search.nut.ts):

    import { execCmd, TestSession } from '@salesforce/cli-plugins-testkit';
    import { expect } from 'chai';

    describe('log search NUT', () => {
      let session: TestSession;

      before(async () => {
        session = await TestSession.create({ devhubAuthStrategy: 'NONE' });
      });

      after(async () => {
        await session?.clean();
      });

      it('command is registered and --help exits 0', () => {
        const result = execCmd('log search --help', { ensureExitCode: 0 });
        expect(result.shellOutput.stdout).to.include('Search for Salesforce users');
      });
    });

    Adapt for each command:
    - trace.nut.ts: execCmd('log trace --help'), expect includes 'Initiate a debug log session'
    - download.nut.ts: execCmd('log download --help'), expect includes 'Download Salesforce debug logs'
    - purge.nut.ts: execCmd('log purge --help'), expect includes 'Delete Salesforce debug logs'
    - filter.nut.ts: execCmd('log filter --help'), expect includes 'Filter downloaded debug logs'

    The text in expect().to.include() must match the first few words of the "# summary" section
    in each messages/log.COMMANDNAME.md file created in Plan 02.

    Use devhubAuthStrategy: 'NONE' for Phase 0 NUTs — no org connection needed to test --help.
    Phase 1+ NUTs will change to devhubAuthStrategy: 'AUTO' when org interaction is tested.
