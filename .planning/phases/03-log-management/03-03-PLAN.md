  <files>src/utils/purge-helper.ts</files>
  <action>
Create new file `src/utils/purge-helper.ts` with functions for orchestrating bulk purge operations.

Export the following functions:

1. `async function queryAllApexLogs(connection: Connection): Promise<ApexLogRecord[]>`
   - Query all ApexLog records in the org (not user-scoped)
   - SOQL: SELECT Id, LogUserId, LogUser.Name, StartTime, LogLength, Status FROM ApexLog ORDER BY StartTime DESC
   - Handle pagination: if result.totalSize > 2000, loop with OFFSET to fetch all records
   - Return array of all ApexLogRecord objects
   - Per RESEARCH.md Pattern 5, retrieve LogLength for all records to calculate freed space
   - Wrap query in executeWithRetry() to handle HTTP 429 rate limiting
   - Per PURGE-01 requirement, get all org logs (not selective)

2. `function calculateFreedSpace(logRecords: ApexLogRecord[]): { count: number; totalBytes: number; totalMB: string; totalGB: string }`
   - Calculate total storage that would be freed by deleting all logs
   - Sum LogLength from all records: totalBytes = sum of LogLength values
   - Convert to MB: totalMB = (totalBytes / 1e6).toFixed(1)
   - Convert to GB: totalGB = (totalBytes / 1e9).toFixed(2)
   - Return object: { count: logRecords.length, totalBytes, totalMB, totalGB }
   - Per PURGE-03 requirement, report freed storage after deletion
   - Per D-07 (locked), show impact before confirmation

3. `async function performBulkDelete(connection: Connection, logIds: string[]): Promise<{ successCount: number; failureCount: number; deletedIds: string[] }>`
   - Delete multiple ApexLog records via Tooling API
   - Use Promise.all to delete in parallel (one connection per delete for safety)
   - For each logId, call connection.tooling.delete('ApexLog', logId)
   - Catch errors per record (e.g., permission, lock issues) — do not fail entire operation
   - Return summary: { successCount, failureCount, deletedIds }
   - Per RESEARCH.md Pattern 5, handle individual failures gracefully
   - Wrap delete calls in executeWithRetry() to handle HTTP 429

4. `function formatPurgeConfirmation(logCount: number, totalMB: string): string`
   - Format confirmation message for user before deletion
   - Return: "Deleting all {count} logs would free ~{MB}MB. Proceed? (yes/no)"
   - Per D-07 (locked), show impact before confirmation
   - Per UX-02 requirement, clear guidance on consequences

5. `function formatPurgeSuccess(deleteCount: number, totalMB: string, failureCount: number): string`
   - Format success message after deletion
   - Return: "Successfully deleted {count} logs. Freed ~{MB}MB." (or include failure count if > 0)
   - If failureCount > 0: append "({failureCount} logs failed to delete due to permissions or locks)"
   - Per PURGE-03 requirement, report freed storage

Imports:
- `{ Connection } from @salesforce/core`
- `{ ApexLogRecord } from '../types/download'`
- `{ executeWithRetry } from './download-helper'`

Error handling:
- Catch errors from queryAllApexLogs: propagate to caller (purge command) with user-friendly message
- Catch errors from performBulkDelete per record: record failure, continue with remaining deletes
- Total failure (all records fail to delete): return all failures, let caller decide whether to report as warning

Per RESEARCH.md Pitfall 6, use Tooling API bulk delete pattern from jsforce (tooling.delete for each record). Do NOT hand-roll bulk delete logic.

Per D-06 (locked), purge targets all org logs (org-wide scope, not user-scoped).
