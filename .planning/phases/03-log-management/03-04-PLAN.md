  - Test: If org has < 100MB remaining quota: download fails with quota exceeded error

  - Test: sf log trace --user-id {userId} --json returns valid JSON

  - Test: After successful retry, download resumes and completes
  - Prerequisite: Requires org with rate limiting enabled or synthetic rate limit injection

Suite 6: Error Handling and Recovery
  - Test: If log body download fails mid-stream: error message shown, partial file cleaned up
  - Test: Error message is actionable (e.g., "Network timeout. Try again" not raw stack trace)
  - Test: If user is not found or has no logs: message "No logs found for user" (not error)
  - Test: Ctrl+C during download: graceful exit with "cancelled" message, partial files cleaned

Suite 7: Multi-Org Support
  - Test: sf log trace --user-id {userId} --target-org {orgName} uses specified org
  - Test: Logs downloaded to org-specific context (if orgName differs, different storage location or org context preserved)
  - Test: Default org used if --target-org not specified
  - Test: Error if --target-org specifies non-existent org: "Unknown target org"

  - Test: User selects "no" → "Purge cancelled" message, no logs deleted, exit code 0
  - Test: User selects "yes" → proceeds to deletion
  - Test: --force flag skips confirmation and deletes immediately per PURGE-02
  - Test: --force + --json combination works (no prompt, structured output)

Suite 3: Storage Space Reporting
  - Test: After deletion, freed space is reported in MB: "Freed ~500MB"
  - Test: Large freed space is shown in GB: "Freed ~1.2GB"
  - Test: Freed space calculation is accurate (sum of LogLength values from deleted logs)
  - Verify: Org quota increases after purge (remaining quota = 1GB - (logs still in org))

Suite 4: No Logs Scenario
  - Test: sf log purge when org has no logs: message "No logs to delete. Your org is clean!"
  - Test: Exit code 0 (not an error condition)
  - Test: No confirmation prompt shown

Suite 5: Permission Errors
  - Test: If user lacks permission to delete logs: error message "You do not have permission to delete debug logs."
  - Test: Suggests next action: "Contact your Salesforce admin."
  - Test: Exit code non-zero (error state)
  - Test: No logs deleted (transaction rolled back or safe failure)

Suite 6: Partial Failures
  - Test: If some logs fail to delete (e.g., locked, read-only): success message includes failure count
  - Test: Output: "Successfully deleted X logs. Freed ~YMB. (Z logs failed to delete due to permissions or locks.)"
  - Test: Successfully deleted logs are removed from org; failed logs remain
  - Test: Exit code 0 (partial success is acceptable)

Suite 7: JSON Output
  - Test: sf log purge --json returns structured result: { deletedCount, failedCount, freedMB, freedGB }
  - Test: JSON is valid and parseable
  - Test: Example: { deletedCount: 50, failedCount: 0, freedMB: "500.0", freedGB: "0.5" }
  - Test: JSON output works with --force flag (no prompt, clean output)
  - Test: Can be piped to downstream tools (e.g., jq) per UX-04

Suite 8: Rate Limiting and Retry
  - Test: If HTTP 429 during bulk delete, executeWithRetry catches and retries with backoff
  - Test: Output shows "Rate limited. Retrying..." message
  - Test: Purge completes successfully after retry
  - Test: Exponential backoff verified: 1s, 2s, 4s delays

Suite 9: Multi-Org Support
  - Test: sf log purge --target-org {orgName} purges logs from specified org
  - Test: Default org used if --target-org not specified
  - Test: Error if --target-org specifies non-existent org
  - Test: Two separate orgs can have independent log counts; purging one doesn't affect other
