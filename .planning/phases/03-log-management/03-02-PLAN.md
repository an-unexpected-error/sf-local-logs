   - Orchestrate complete download workflow after trace flag is created
   - Input: org connection, traceResult (from Phase 2), traced userId, userName
   - Process:
     a. Calculate download time window: calculateDownloadTimeWindow(traceResult.createdAt)
     b. Query ApexLog records: queryApexLogsForUser(connection, userId, startTime, endTime)

     d. Create session directory: createSessionDirectory(userId, userName, traceResult.createdAt)
     e. For each log: 
        - Check quota before download: validateQuotaAvailable(connection, log.LogLength)
        - If quota exceeded: throw error with D-05 message format
        - Stream download: streamDownloadToFile(connection.request(...), filePath)
        - Track: DownloadResult with success=true, filePath, bytesDownloaded
     f. Return array of DownloadResult for all logs
   - Per D-04 (locked), check quota during download, not upfront
   - Per DOWNLOAD-01, download logs scoped to traced user + timeframe
   - Per DOWNLOAD-02, return progress data for display (file count, total bytes)
   - Error handling: if quota exceeded mid-download, throw error; caller will handle with error message

3. `function formatDownloadProgress(filesDownloaded: number, totalBytes: number, elapsedSeconds: number, logRecords: ApexLogRecord[]): string`
   - Format download progress for display per DOWNLOAD-02 requirement
   - Return: "Downloaded %d of ~%d log(s) • %dMB • ETA: %s" where:
     - filesDownloaded = count of successfully downloaded files
     - ~totalCount = estimated remaining (total records queried - already downloaded)
     - totalBytes = sum of all LogLength values downloaded so far
     - ETA = calculateETA(bytesDownloaded, totalBytes, elapsedSeconds)
   - Note: total log count is unknown (logs generated concurrently); show count downloaded and rough estimate, not percentage
   - Per D-03 (locked), progress shows time elapsed, ETA, and file count

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Trace command → Download handler | TraceResult and userId from Phase 2 trace creation; assumed valid by trace completion |
| Org connection → Salesforce APIs | Tooling API ApexLog queries and REST Limits API quota checks |
| Download stream → Local filesystem | Large ApexLog body streamed to disk; must validate file path and handle write errors |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-07 | Denial | Download progress loop without timeout | mitigate | Set timeout on Connection.request() calls (e.g., 30s default); fail fast if exceeded; user can retry |
| T-03-08 | Tampering | Partial file writes on network failure or SIGINT | mitigate | Catch SIGINT in download loop; clean up partial .json files before exit; track completion state in metadata |
| T-03-09 | Information Disclosure | Sensitive log content written to local storage | accept | Logs contain user activity data; stored locally in user's home directory (user-controlled); v1 does not add encryption |
| T-03-10 | Denial | Concurrent quota checks during parallel download+watch | mitigate | Use consistent connection object; Salesforce quota enforcement is authoritative (plugin enforcement is safety net) |
| T-03-11 | Authorization | Download all logs for traced user (not permission-gated by plugin) | mitigate | Rely on Salesforce Tooling API permission boundary; org connection already authenticated and authorized |
| T-03-12 | Tampering | MultiBar progress display vulnerable to log injection | mitigate | Sanitize all string inputs to progress bar (file count, ETA, paths); escape special characters |

</threat_model>
